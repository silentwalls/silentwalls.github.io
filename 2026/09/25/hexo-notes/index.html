用 Hexo 和 GitHub Pages 搭一个安静的角落

技术 # Hexo # GitHub Pages # 教程

静态博客的好处是：没有数据库，没有后台，没有需要定期升级的插件。写完 Markdown，推上去，网站就更新了。

这篇记录一下整个过程，也当做给自己的备忘。

三步走

  1. 本地安装 Hexo，生成站点；
  2. 在 source/_posts 里写 Markdown；
  3. 推到 GitHub，由 Pages 托管。

命令很短：

npm install
npx hexo server      # 本地预览 http://localhost:4000
npx hexo generate    # 生成静态文件到 public/
npx hexo deploy      # 推送到 GitHub Pages

目录结构

路径 作用
_config.yml 站点配置：标题、作者、网址、部署
source/_posts 所有文章（Markdown）
source/images 图片资源
source/_data 结构化数据，比如友链
themes/silentwall 主题：模板 + 样式

一篇新文章长什么样

---
title: 标题
date: 2026-09-25 22:30:00
categories: 随笔
tags:
  - 标签
cover: /images/covers/post-3.jpg
---

正文从这里开始。

--- 中间那一段叫 front-matter，是这个文件的「说明书」。标题、时间、分类、标签、封面都在这里写。

一个坑

如果 _config.yml 里的 url 和 root 没改对，本地看着好好的网站，部署之后会样式全丢。

用户站点是 https://用户名.github.io，root 填 /；
项目站点是 https://用户名.github.io/仓库名，root 要填 /仓库名/。

记住这一条，能省掉一个晚上。
